# 플레이어 성장 + 월드 허브 통합 설계안

작성: 2026-10-06 · 상태: 제안 / 구현 전

사용자는 판마다 끝나는 점수 외에 누적되는 플레이어 성장, 피로하지 않은
레벨 상승, 프로필과 내 정보의 표현 방향을 요청했다. 앞서 논의한 입체적인
공통 HUD, 지도 확대·이동, 한 지역 30개 스테이지와 같은 개발 범위로 연결한다.
이 문서는 제품 코드나 라이브 배포를 변경하지 않는다. 보상은 꾸미기·수집
중심을 기본 제안으로 두며, 사용자의 보상 방향 답변에 따라 확정한다.

추가 요청인 개인 플레이 기록은 [내 플레이 기록 설계](./player-stats-plan.md)에
정의한다. 같은 통합 개발에 포함하되 수치는 설명 문단 대신 아이콘·짧은
타이틀·숫자 그룹으로 보여 주며, 성장과 개인 통계의 정산 목적을 구분한다.

## 확인한 현재 상태

- `src/main.ts`의 `home-level`은 자유 플레이의 최고 도달 단계다. 최고 점수와
  도달 단계는 저장되지만 누적 XP나 별도의 플레이어 레벨은 없다.
- `src/ui/profile.ts` / `index.html`의 내 프로필은 얼굴, 이름, 캐릭터 편집,
  계정 상태를 표시하며 성장 정보는 없다. 로컬 런타임에서도 확인했다.
- 캠페인은 네 지역 × 다섯 미션이다. 완료 이력과 최초 보상은 기기 로컬에
  저장된다. 구글 로그인 및 친구 프로필 기능이 있다고 캠페인이 동기화되는
  것은 아니다. `src/social/players.ts`에도 누적 XP 데이터는 없다.
- 공개 순위의 `LeaderboardEntry.level`은 기록된 판의 도달 단계다.
  여기에 플레이어 성장 레벨을 덮어쓰면 기록의 의미가 바뀐다.
- 기존 v6 미션 순서·시드·목표·이동 예산은 리플레이 계약이다. 새 캠페인
  확장은 새 규칙 버전을 사용하고, 이전 저장과 기록은 그대로 해석해야 한다.

## 목표와 제외 범위

짧게 플레이해도 지난 활동이 남고, 다음 작은 성취와 보상이 보이게 한다.
대상은 모바일에서도 캐릭터를 꾸미며 퍼즐을 즐기는 플레이어다. 이용 빈도,
연령, 이탈 원인 및 경험치 선호는 실제 사용자 조사로 확인된 사실이 아니다.

- 판 점수, 지역 스테이지, 플레이어 레벨을 분리한다.
- 플레이어 레벨과 XP는 실패하거나 다음 판을 시작한다고 감소하지 않는다.
- 이름, 성별 표현, 캐릭터 외형과 복장을 바꿔도 같은 플레이어의 성장과 보상은
  유지된다. 레벨은 특정 3D 모델이나 아바타 코드에 종속시키지 않는다.
- 새로운 지역을 탐험하는 활동을 우대하되 재도전과 자유 플레이도 성장한다.
- 레벨을 이유로 기본 아이템, 기존 헤어·옷·편집 기능 또는 이미 열린 지역을
  잠그지 않는다. 지역 진행은 지역 클리어 조건으로 결정한다.
- 지속적인 퍼즐 능력 강화, XP 판매, 의무 출석·연속 접속, 경험치 만료,
  자동 환생·시즌 레벨 초기화는 기본 제안에서 제외한다.
- 첫 구현은 기기 로컬 성장이다. 계정 단위 클라우드 성장·친구의 성장 레벨
  공개에는 데이터 모델, 권한 및 동기화 설계가 별도로 필요하다.

## 서로 다른 세 가지 숫자

| 정보 | 의미 | 대표 표기 |
| --- | --- | --- |
| 판 점수 | 이번 플레이의 기록과 목표 | 4,230점 |
| 지역 진행 | 월드의 클리어 여정 | 보석숲 12/30 |
| 플레이어 레벨 | 판을 넘어 누적된 성장 | Lv.8 |

한국어뿐 아니라 네 언어에서 성장 레벨과 퍼즐 단계의 명칭을 분리한다.
지역 번호, 기존 자유 플레이 기록의 단계 및 성장 레벨은 서로 환산하지 않는다.

## XP와 상승 곡선: 플레이테스트 전 초기안

### 획득

- 캠페인 스테이지 클리어: 40 XP.
- 그 스테이지의 최초 클리어: 추가 60 XP. 최초 합계는 100 XP이며 논리적으로
  같은 스테이지를 리플레이하거나 버전이 바뀌었다고 최초 보상을 다시 주지 않는다.
- 재도전 클리어: 40 XP. 새로 플레이한 시도는 보상되지만 이미 정산된 동일한
  시도·기록을 다시 읽는 것은 새 플레이가 아니다.
- 자유 플레이: 검증된 단계 클리어마다 40 XP. 중간 체크포인트에서 확정한
  경험치는 그 뒤 실패하거나 종료해도 남는다. 같은 단계 결과의 재표시는 제외한다.
- 이동 횟수가 소진된 실제 실패: 현재 목표의 달성 비율에 따른 0~15 XP.
  초기 계산은 `floor(15 × clamp(목표 진행 / 목표량, 0, 1))`다. 이전 단계의
  정산 XP와 별개로 마지막 미완료 단계만 대상으로 한다.
- 즉시 종료·중도 포기, 입력 없는 진입, 잘못된 리플레이, 공유 기록 감상에는
  미완료 단계 XP를 지급하지 않는다. 이미 확정한 성장과 체크포인트는 유지한다.
- 점수, 폭발 개수, 콤보마다 XP를 직접 곱하지 않는다. 지역별 규칙의 점수 차이와
  무한 연쇄가 성장 효율을 지배하지 않게 한다. 플레이어 레벨은 실력 순위가 아니다.

### 요구량

현재 Lv.L에서 다음 레벨까지 필요한 경험치:

`필요 XP(L) = 100 + 10 × min(L - 1, 10)`

처음은 100 XP, 이후 조금씩 증가하며 Lv.11부터 200 XP로 유지한다. 이 상한은
레벨 상승에 필요한 XP의 상한이지 획득량이나 플레이어 레벨의 상한이 아니다.
초과 XP는 다음 레벨로 이월하고, 한 정산에 여러 레벨이 올라도 모두 반영한다.

| 신규 플레이어의 서로 다른 최초 클리어 | 예상 레벨 | 레벨 내 XP / 다음 요구량 |
| --- | --- | --- |
| 1개 | Lv.2 | 0 / 110 |
| 5개 | Lv.5 | 40 / 140 |
| 10개 | Lv.8 | 90 / 170 |
| 20개 | Lv.13 | 150 / 200 |
| 30개 | Lv.18 | 150 / 200 |

이 표는 최초 클리어 100 XP만 합산한 수학적 결과다. 실패·재도전·이전 기록
이전은 포함하지 않았다. 플레이 시간이나 피로 감소를 검증한 결과가 아니다.
일반 재클리어만으로도 후기에는 다섯 판당 한 레벨 상승이 가능한 초기안이다.

## 피로를 줄이기 위한 제품 가설

- 점점 수십 판을 요구하는 경험치 곡선을 피한다. 먼저 꾸준한 작은 상승을
  검증하고, 나중에 필요하면 상승 곡선과 레벨 보상의 빈도를 각각 조정한다.
- 매 레벨에는 소량 코인을 제안한다. 정확한 수량은 기존 아이템 가격·최초
  클리어 보상과 함께 경제 검증 후 확정한다. 새 보상으로 기존 가격을 임의 변경하지 않는다.
- Lv.3·5·10·15·20 등 이정표에는 새 프로필 프레임, 칭호, 추가 보상 연출을
  배치한다. 기존 꾸미기 기능을 다시 잠근 뒤 해금시키는 방식은 사용하지 않는다.
- 다음 한 가지 보상을 미리 보여 주되 긴 미션 목록과 의무 과제를 지도에
  늘어놓지 않는다. 지급된 외형을 장착하는 행동은 선택이며 보상은 자동 확정한다.
- 하루를 쉬거나 도중에 멈춰도 레벨·XP·이미 받은 외형이 줄지 않는다.
- 레벨업은 기존 결과 화면의 일부다. 별도의 필수 확인 창이나 반복 연출을
  추가하지 않고 다음 플레이를 바로 누를 수 있게 한다.

성장 체감과 선택권에 초점을 두는 것은 게임 즐거움과 자율성·유능감의 관련성을
다룬 [Ryan, Rigby, Przybylski의 연구](https://selfdeterminationtheory.org/SDT/documents/2006_RyanRigbyPrzybylski_MandE.pdf)를
참고한 설계 판단이다. 이 연구가 위 XP 수치나 본 게임의 피로 감소를 입증하지는 않는다.

## 화면별 정보와 인터랙션

| 화면 | 표시와 행동 |
| --- | --- |
| 지도·캐릭터·상점 공통 헤더 | 얼굴을 가리지 않는 입체 Lv.배지, 이름, 작은 XP 바. 프로필을 누르면 내 정보. 재화와 XP는 모양·단위로 구별. |
| 내 정보 | 큰 얼굴과 Lv., 현재 XP / 다음 요구량, 다음 보상 미리보기, 장착한 프레임·칭호, 지역 완료 기록. 이름 수정·캐릭터 편집·계정 기능 유지. |
| 캐릭터 | 전신 미리보기와 기존 편집 동작 유지. 해금한 프레임·칭호를 선택·장착하고 공통 프로필에 즉시 동일하게 반영. |
| 게임 중 | 목표·얼굴 반응·남은 이동 횟수와 보드가 우선. 큰 XP 바나 성장 패널은 두지 않음. 레벨을 표시해도 고정 크기 작은 배지로 제한. |
| 클리어·실패 결과 | 이번 XP와 확정된 성장 진행을 함께 표시. 상승한 경우 Lv.이전 → Lv.현재, 보상 요약. 다시 하기·다음 스테이지가 항상 바로 사용 가능. |
| 순위·친구 | 기존 실력 기록을 유지. 기존 L표시는 판의 단계이며 플레이어 Lv.로 위장하지 않음. 친구의 성장 Lv.는 클라우드 데이터 계약 이후 별도 추가. |

공통 HUD는 지도 카메라와 독립적으로 고정하며 지도·캐릭터·상점 전환으로
흔들리지 않는다. 실제 게임에 진입하면 공통 내비게이션은 숨긴다. 프로필과
상세 정보 창에서는 현재 문맥과 선택 지역을 잃지 않게 한다.

입체적 배지와 버튼은 앞서 합의 중인 캐주얼 게임의 동일한 광원·두께·접지
그림자 방향을 따른다. 프레임과 배지는 얼굴, 편집 표시, 초점 표시를 자르지 않는다.
수치 예: 헤더의 `Lv.8`, 내 정보의 `90 / 170 XP`, 다음 보상으로 `Lv.10 · 프레임`.

### 레벨업 연출

결과 화면의 XP가 채워지고 배지가 전환된 뒤, 캐릭터가 짧게 반응한다.
공통 헤더로 돌아왔을 때 새로운 배지와 진행이 유지된다. 여러 레벨을 올렸다면
한 번의 `Lv.8 → Lv.10` 요약으로 보여 주고 필수 창을 두 번 띄우지 않는다.
연출 종료를 기다려야 다음 버튼을 누를 수 있는 방식은 사용하지 않는다.

획득·레벨업 애니메이션이 끝나도 결과는 내 정보에서 다시 확인할 수 있다.
이는 진행과 목표를 언제든 확인할 수 있게 하라는
[Xbox 접근성 가이드 109](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/109)를
참고한 정보 배치다. 감소된 모션 설정에서는 정적인 수치·배지·텍스트로 대체한다.

## 저장·정산·기존 사용자 보호

- `totalXp`를 성장의 기준으로 삼고 레벨과 진행률은 같은 버전의 함수로
  계산한다. 따로 저장한 level과 xp가 서로 불일치하지 않게 한다.
- 플레이 시작 때 생성하고 중간 저장에도 남기는 안정적인 시도 ID와
  결과 검증을 연결한다. XP는 별도 메타 원장에서 관리하며 기존 퍼즐의
  `RunRecord.level`, 시드, 액션 및 점수 검증을 변경하지 않는다.
- 시도/단계 XP, 스테이지 최초 보너스, 레벨 보상에 각각 안정적인 지급 ID를
  둔다. 언어 변경, 결과 재표시, 새로고침, 이어하기 및 다른 탭은 같은 지급을 반복하지 않는다.
- XP·획득 권리·보상 지급은 트랜잭션으로 정산한다. 기존 코인 키를 별도로
  증가시키는 단순 추가로 지급 누락·중복 위험을 늘리지 않는다. 초기 로컬
  구현에는 브라우저의 트랜잭션 저장소를 검토하고 새로운 의존성은 불필요하게 추가하지 않는다.
- 확정 저장과 애니메이션을 분리한다. 저장 실패를 성공으로 표시하지 않고
  미저장 상태·재시도·기존 복구 가능한 기록을 유지한다. 손상 데이터를
  만났다고 이전 유효 데이터를 자동으로 삭제하지 않는다.
- 기존 지역 완료 이력은 명시적인 일회성 이전 원칙으로 초기 XP에 반영한다.
  기준은 현재 스키마가 인식하는 완료 미션이다. 최고 점수나 최고 도달
  단계를 플레이어 레벨로 바꾸지 않는다. 보상 이전도 하나의 지급 이력으로 정산한다.
- 기존 스테이지와 새 캠페인의 대응표를 확정하고 동일한 콘텐츠가 단순
  버전 변경으로 최초 XP를 재지급하지 않게 한다. v6 저장·리플레이는 보존한다.
- 로컬 성장 원장은 로컬 데이터다. 이전 이력의 XP 환산은 서버 검증을 받은
  계정 기록이라는 의미가 아니다. 공유 순위나 경쟁 보안의 근거로 쓰지 않는다.
- 첫 버전은 현재 기기의 성장임을 내 정보에 표시한다. 브라우저 데이터 삭제나
  다른 기기에서는 유지되지 않을 수 있다. 로그인만으로 성장 동기화를 약속하지 않는다.
- 로그인·게스트 전환에서 성장의 소유자를 정의하고 다른 계정 데이터를
  덮어쓰거나 자동 합산하지 않는다. 익명 UID 유지와 기존 구글 계정 전환은
  다른 경로다. 계정 스코프를 구현할 경우 게스트 이전은 명시적이고 일회성이어야 한다.

## 상태·반응형·접근성

신규 Lv.1 / 기존 데이터 이전 / 일반 상승 / 다중 상승 / 실패 / 재도전 /
이어하기 / 지급 대기 / 저장 실패 / 오프라인 / 계정 전환을 명시적으로 처리한다.

- 신규 사용자는 빈 통계 대신 Lv.1과 첫 보상의 짧은 미리보기를 본다.
- XP 바만으로 진행을 설명하지 않는다. 상세 화면에 현재 XP와 다음 요구량을
  텍스트로 표시하고, 헤더에도 접근 가능한 전체 레벨·진행 이름을 제공한다.
- 키보드로 프로필·보상 장착·결과 액션을 사용할 수 있어야 한다.
- 모바일 안전 영역과 44px 목표 크기를 보장하고, 글자 확대·긴 이름·네 언어·
  높은 레벨에서도 얼굴·배지·지갑·설정이 겹치지 않아야 한다.
- 보드의 고정 피드백 영역, 프로필 반응 범위와 레이아웃 안정성을 보존한다.
  성장 연출이 보드를 밀거나 화면 상단에서 잘리지 않아야 한다.
- 스크린리더 알림은 정산 결과 단위로 한 번만 하고 애니메이션 프레임마다
  변경 수치를 읽지 않는다. 보상은 시간 내 확인하지 않았다고 사라지지 않는다.

## 함께 구현할 순서

1. 플레이어 성장·보상 원장과 단위 테스트, 기존 기록 이전 기준을 확정한다.
2. 공통 입체 HUD와 지도/캐릭터/상점 내비게이션에 성장 표시를 연결한다.
3. 전체 지도 ↔ 지역 확대·이동 및 지역 지도 좌표를 구현한다.
4. 새 캠페인 버전으로 첫 지역 30개 스테이지를 설계하고 성장 속도와 함께 검증한다.
5. 내 정보, 결과 정산, 외형 보상 장착, 개인 플레이 통계, 연출과 접근성 처리를 연결한다.
6. 회귀·반응형·저장·오프라인 검증 후 하나의 릴리스로 배포한다.

한 릴리스로 제공하더라도 구현·검증은 위 단위로 나눈다. 지도 아트, 카메라,
스테이지 정의, 보상과 성장 함수는 분리해 이후 지역 추가가 화면 재작성이나
기존 기록 초기화를 요구하지 않게 한다.

## 완료 기준과 검증 계획

- 계산 함수는 경계 XP, 0 XP, 초과 XP, 여러 레벨 상승, 음수·비정상 입력을 검증한다.
- 최초/재클리어/실패/자유 플레이의 목표 종류별 XP가 같은 정책으로 계산된다.
- 같은 시도와 최초 보상이 결과 재표시·새로고침·이어하기·다른 탭에서 중복되지 않는다.
- 저장 중 종료·할당량 실패·손상 데이터에서 이전 정상 성장과 지급 권리가 복구 가능하다.
- 기존 20개 미션, 지갑, 캐릭터, v1-v6 저장·리플레이와 순위의 의미가 유지된다.
- 이름 변경·캐릭터 편집·아바타 파일 복원 때문에 플레이어 XP가 초기화되지 않는다.
- 모바일·가로·태블릿·폴더블 크기, 네 언어, 글자 확대, 감소된 모션, 키보드에서
  UI가 겹치지 않고 게임판 면적과 입력이 회귀하지 않는다.
- 30개 신규 스테이지 최초 클리어만의 계산은 Lv.18 / 150 XP와 일치한다.
  실제 플레이테스트에서는 레벨업 간 판 수·시간, 재도전 횟수, 완료 분포,
  보상 이해도와 보고된 피로감을 살핀다. 봇 통과율은 사람의 피로 검증을 대신하지 않는다.
- 코드 구현 후 저장 모듈·정산 단위 테스트, `npm run typecheck`, `npm test`,
  프로덕션 빌드 및 대상 브라우저 흐름 검증을 실행한다. 라이브 반영은 별도로
  배포 커밋·아티팩트·실제 화면 일치를 확인한 다음 완료라고 보고한다.

설계 단계에서 수행한 검증은 현재 소스·내 프로필 런타임 확인과 경험치 곡선
계산이다. 제품 코드, 새 경험치 기능, 사용자 피로감 및 라이브 배포는 아직 검증하지 않았다.
