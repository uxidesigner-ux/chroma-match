# 내 플레이 기록 설계안

작성: 2026-10-06 · 상태: 제안 / 구현 전

플레이어 성장 설계의 추가 범위다. 사용자는 아이템 사용량과 판당 평균처럼
실제 플레이 동작을 유의미한 기록으로 보여 주되, 긴 설명 대신 아이콘·짧은
타이틀·숫자를 한 그룹으로 표시하기를 요청했다. 제품 코드나 수집 기능은
아직 변경하지 않는다. [성장 통합 설계](./player-growth-plan.md)와 함께 구현한다.

## 현재 수집 접점과 한계

- `Game.useItem()`은 실제 소모에 성공한 뒤 `item` 액션과 `onItemUsed`를 남긴다.
  망치·로켓·폭탄별 실제 사용 횟수의 근거로 활용할 수 있다.
- `onClear`, `bestCombo`, `onFusion`은 보석 제거, 최고 연쇄, 특수 보석 합체의
  수집 접점이다. 이벤트 수와 사용자가 한 행동 수는 같은 개념이 아니다.
- `onPowerCreated`는 매치로 만든 특수 보석뿐 아니라 보너스·피버 자동 공급에도
  사용된다. '직접 만든 특수 보석'이라면 생성 출처를 추가로 구분해야 한다.
- `src/missions.ts`의 기록은 날짜별로 교체된다. 오늘의 사용량을 사용자의
  평생 누적 기록으로 해석할 수 없다.
- `RunRecord`는 시드와 수락된 액션을 저장하지만, 모든 과거 시도와 결과를
  담은 기록장이 아니다. 취소 입력, 시도 식별자, 활동 시간도 포함하지 않는다.
- `restoreRun()`은 게임 훅을 끈 채 재구성한다. 복원 도중 일어난 계산을
  새로운 플레이로 집계하거나, 훅만 듣다가 복원 전 통계를 잃어서는 안 된다.

## 정보 배치와 기본 그룹

내 정보는 얼굴·Lv.·XP·다음 보상이 우선이고, 그 아래에 '내 플레이'를 둔다.
지도 헤더와 실제 게임판에는 통계 패널을 추가하지 않는다. 결과 화면에서는
기록을 갱신하고 새로운 최고 연쇄 같은 실제 개인 기록 하나만 짧게 강조한다.

모바일 기본은 두 열 × 세 행의 간결한 숫자 그룹이다. 하나의 패널 안에서
아이콘, 타이틀, 수치와 단위를 묶고, 각 그룹을 큰 설명 카드로 만들지 않는다.
정보 그룹을 눌러야 하는 버튼처럼 표현하지 않는다. 입체 아이콘은 공통 게임
UI와 같은 스타일을 쓰되 통계 숫자보다 더 강하게 강조하지 않는다.

아래 수치는 화면 구성 예시이며 실제 사용자의 기록이 아니다.

| 아이콘 역할 | 타이틀 | 수치 예시 |
| --- | --- | --- |
| 도구 | 아이템 사용 | 126개 |
| 게임판 + 도구 | 판당 사용 | 2.6개 |
| 연결된 보석 | 최고 연쇄 | ×8 |
| 반짝이는 특수 보석 | 직접 만든 특수 | 327개 |
| 두 특수 보석 결합 | 특수 합체 | 34회 |
| 도구 없는 완료 표시 | 무아이템 클리어 | 12판 |

사용 아이템의 세부 구성은 같은 영역의 짧은 아이콘 행으로 제공한다.
예: 망치 26 / 로켓 28 / 폭탄 72. 실제 UI에는 기존 아이템 아트를 재사용한다.
아이콘만 보고 의미를 추측하게 하지 않고 짧은 타이틀과 단위를 함께 유지한다.

## 집계 범위와 '한 판'의 정의

- 기본 범위는 모험(캠페인)이다. 자유 플레이는 별도 범위로 전환한다.
  캠페인 한 판은 한 미션의 시도, 자유 플레이 한 판은 여러 단계를 이어가는
  한 런이다. 평균을 한데 섞으면 같은 숫자로 서로 다른 활동을 비교하게 된다.
- '누적 / 최근 20판'을 짧은 선택 컨트롤로 제공한다. 선택한 모드와 기간이
  모든 그룹에 동일하게 적용되고, `최근 12판`처럼 실제 표본 수도 표시한다.
- 집계 대상은 최소 한 번의 실제 보드 변경 행동 후 클리어·실패·명시적
  중도 종료로 확정된 시도다. 입력 없는 진입, 취소된 준비 화면, 공유 기록
  감상은 제외한다. 실패와 실제 행동이 있었던 중도 종료도 기록에서 숨기지 않는다.
- 일시정지, 새로고침, 탭 비활성화 및 이어하기는 새로운 판이나 종료가 아니다.
  진행 중인 시도는 중간 저장하고, 종료 때 같은 ID로 한 번만 반영한다.
- 판당 사용은 같은 집계 대상의 `아이템 사용 합계 / 판 수`다. 무아이템 판도
  분모에 포함한다. 예시 126개 / 48판은 소수 한 자리로 2.6개다.
- 모험/자유, 지역 규칙 및 게임 버전을 기록에 남긴다. 지역의 자동 공급 차이를
  플레이어의 실력 차이처럼 평가하지 않는다. 필요하면 지역별 상세 범위를 제공한다.

## 각 숫자가 뜻하는 것

- 아이템 사용: 실제 실행된 `item` 액션 하나를 한 개로 집계한다. 선택·취소·
  구매·초기 지급·가방에 가져온 추가 재고·특수 보석 발동은 사용량이 아니다.
- 최고 연쇄: 게임이 계산하는 `bestCombo`의 최댓값이다. 제거 이벤트나
  파티클 개수를 더해서 연쇄 횟수로 만들지 않는다.
- 직접 만든 특수: 매치 결과로 새로 만들어진 특수 보석만 집계한다.
  처음 놓인 특수 보석, 화산·피버·릴레이 자동 공급은 제외한다.
- 특수 합체: 플레이어가 인접한 특수 보석을 교환해 합체가 수락된 행동 수다.
  그 뒤 연쇄로 여러 특수가 발동해도 같은 합체 행동은 한 번이다.
- 무아이템 클리어: 모험에서는 그 시도를 클리어했고 수동 아이템 사용이
  0개인 판 수다. 자유 플레이에서는 실제로 한 단계 이상 클리어한 런이며
  런 전체 사용이 0개인 판 수다. '클리어'는 완주와 단계 달성이므로 범위별
  접근 가능한 이름에서도 명확히 구분한다. 가방 재고 장착과 실제 사용도 구분한다.

## 플레이 성향 표현

현재는 관측 가능한 기록만 보여 준다. '절약형', '공격형' 같은 유형을
고정된 성격이나 실력 평가로 붙이지 않는다. 필요하면 최근 기록에서
`자주 쓰는 아이템 · 폭탄`, `아이템 없이 · 7/20판` 같은 짧은 그룹을 제공한다.
아이템 사용이 많다고 나쁜 플레이로 표시하거나 특정 행동을 강요하지 않는다.
사용 기록의 크기와 종류로 플레이어 XP, 다음 지역 접근 또는 구매 가격을
자동 변경하지 않는다. 사용자 관찰 없이 재미·만족도 향상을 확정하지 않는다.

## 저장과 개인정보 범위

- 성장 원장과 같은 안정적인 시도 ID를 사용하되, 통계 기록과 XP 지급 조건은
  분리한다. XP를 주지 않는 중도 종료도 실제 사용 내역은 통계에 남는다.
- 중간 저장은 시도의 스냅샷·수락된 액션 커서와 함께 처리한다. 재구성 가능한
  결정적 통계와 이벤트 출처를 기록하며, UI 애니메이션 훅을 단독 원장으로 쓰지 않는다.
- 동일 ID의 스냅샷은 교체 또는 미반영 차분으로 처리한다. 복원·결과 재표시·
  언어 변경·다른 탭이 누적 숫자를 두 번 증가시키지 않게 한다.
- 누적 합계와 최근 20판 요약을 보관한다. 모든 터치·마우스 이동을 끝없이
  저장하거나 새 외부 분석 SDK를 추가하지 않는다. 지급 이력과 진행 중 시도는
  별도 목적에 맞게 보존하고, 최근 상세 목록을 줄인다고 성장 권리를 잃지 않는다.
- 처음에는 기기 로컬의 본인 기록이다. 친구·공개 순위에 자동 공개하거나
  외부 분석 서버로 전송하지 않는다. 계정 동기화는 별도 설계와 범위다.
- '통계만 초기화'를 지원하되 XP·레벨·코인·스테이지 완료와 캐릭터는 보존한다.
  초기화 기준을 저장해 과거 원장을 다시 읽는 것만으로 통계가 부활하지 않게 한다.
- 과거 누적 사용량은 데이터가 없어 복원할 수 없다. 최고 점수나 오늘의
  미션 기록으로 만들어 채우지 않는다. 새 기록의 시작 시점을 유지한다.
  이전 버전의 진행 중 판은 추적되지 않은 구간을 식별하고 완전한 판 평균에
  섞지 않는다. 기록을 잃었다는 인상을 주는 가짜 0도 표시하지 않는다.

## 상태와 완료 기준

- 첫 기록이 없으면 평균·연쇄는 `—`, 알려진 새 집계의 사용 합계는 0으로
  표시한다. 미수집·불러오기 실패·실제 0을 같은 상태로 취급하지 않는다.
- 최근 20판보다 적으면 있는 판 수로 계산하고 표본 수를 함께 표시한다.
- 긴 번역, 큰 숫자, 글자 확대에서도 아이콘·타이틀·숫자가 다른 그룹처럼
  흩어지거나 잘리지 않아야 한다. 필요하면 한 열로 재배치한다.
- 정보는 의미 있는 목록/용어·값 구조로 읽히고 아이콘은 텍스트와 중복해서
  읽지 않는다. 범위 선택과 초기화는 키보드로 가능하며 초점이 보인다.
- 카운터 연출은 확정된 기록만 대상으로 짧게 실행하고, 감소된 모션에서는
  바로 표시한다. 숫자 변화의 매 프레임을 스크린리더로 읽지 않는다.
- 회귀 검증은 사용 성공/실패/취소, 초기 공급과 구매 제외, 무아이템 판을
  포함한 평균, 직접 생성과 자동 공급 구분, 합체 다중 발동, 종료 유형,
  0판·부분 이력, 최근 목록 교체, 이어하기·새로고침·다중 탭, 저장 실패,
  통계 초기화 후 성장 보존을 포함한다.

이번 단계에서 확인한 것은 현재 코드의 수집 접점과 집계 제약이다.
개인 통계 수집·표시·실데이터 검증·라이브 반영은 아직 수행하지 않았다.
