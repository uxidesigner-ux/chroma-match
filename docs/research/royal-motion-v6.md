## 형태와 재질에서 큰 차이

1. **특수 생성**: 기존 색 블록이 중심으로 모인다. 새 아이템은 작은 밝은 점에서 커지고, 잠깐 정상 크기를 넘은 뒤 자리를 잡는다. 화면에 새 그림이 즉시 나타나는 것만으로는 부족하다.
2. **TNT**: 황백색 중심은 실제 면적을 채운다. 주변에는 황금빛 방사광과 잠깐의 주황색 가장자리, 흩어진 고체 파편이 함께 있다. 현재 v5의 비어 있는 원 테두리는 핵심 질감이 빠져 있다.
3. **프로펠러**: 빨강/금색 원반과 짙은 아래 몸체가 읽힌다. 회전날개가 빠르게 흐려져 타원형 원반처럼 보이고, 출발 때 일반 조각보다 약 1.3–1.5배 큰 실루엣을 보인다. 전체 이미지의 빠른 회전과 점선 궤적은 제공 영상에서 관찰되지 않는다.
4. **일반 블록 파손**: 작은 파란 단단한 조각, 녹색 조각과 흰 반짝임이 함께 나온다. 모든 색에서 동일한 별 모양만 나오는 효과와 다르다.
5. **장애물 파손**: 선물은 크게 휘어진 버건디 조각·금색 띠·청색 리본이 구분된다. 새장은 주황색 나무 틀과 보라색 조각이 넓게 튀며 회전한다. 몇 조각은 셀의 1/4–1/2 크기까지 보인다. 이는 물체별로 다른 파편 묶음이 필요한 근거다.
6. **낙하와 착지**: 블록은 연속된 경로를 따라 움직인다. 착지의 짧은 수직 압축은 블록을 가로세로 똑같이 부풀리는 효과보다 가깝다. 파편과 스파클은 착지/다음 연쇄가 시작된 뒤에도 남는다.

## 로켓·라이트볼에 대한 근거 범위

제공 영상에는 로켓과 라이트볼의 발사·폭발이 보이지 않는다. 따라서 이 두 종류의 정확한 궤적, 광선 색, 지연 시간, 조합 전체를 영상에서 측정했다고 보고하지 않는다.

Dream Games 공식 도움말은 로켓이 행/열을 지우며, 프로펠러가 출발할 때 이웃 칸도 지우고, TNT가 두 칸 반경, 라이트볼이 같은 색을 지운다고 설명한다. 이는 **동작 범위**의 근거이며 애니메이션 시간의 근거는 아니다. [Creating and Using the Power-Ups](https://dreamgames.helpshift.com/hc/en/3-royal-match/faq/6-creating-and-using-the-power-ups/)

공식 조합 설명에는 로켓+TNT의 세 행/세 열, 프로펠러가 다른 아이템을 운반하는 조합, 라이트볼의 색 블록 변환이 나온다. v6에서 그런 결과를 애니메이션으로 보여줄 수 있으나, 제공 영상과 동일한 연출이라고 부르지 않는다. [Power-up Combinations](https://dreamgames.helpshift.com/hc/en/3-royal-match/faq/7-power-up-combinations/)

## 구현 후 검수 항목

- 유효한 일반 스왑에서 두 조각이 먼저 이동하고, 중간에 순간 삭제·중복 표시되지 않는지.
- 특수 생성에서 기존 조각의 응집과 새 아이템의 출현이 읽히는지.
- TNT의 발동 위치·충격 위치·장애물 피해가 일치하며, 잔해가 다음 낙하를 막지 않는지.
- 프로펠러의 출발·비행·도착이 구분되고 대상의 피해가 도착 전에 발생하지 않는지.
- 새 조각이 실제 보드 위/세그먼트 입구에서 내려오고, 여러 칸 낙하가 눈에 보이는지.
- 동시에 움직이지 않는 영역의 입력, 연쇄 종료 판정, 재시작 시 남은 효과 정리, reduced motion을 유지하는지.
- 모바일 화면에서 실제 프레임을 확인하고, 정지 스크린샷만으로 모션 개선을 판정하지 않는지.

## v6 통합 후 직접 시각 검수

390×844의 별도 Chrome 컨텍스트에서 실제 게임 UI의 보드 편집기로 검수용 레벨을 가져온 뒤 포인터 입력을 보냈다. 운반 중 공격과 추가 입력뿐 아니라 연쇄 그룹까지 겹침을 보호하는 최종 엔진 수정 후, 7×7의 생성/연쇄/조합 세 장면과 12297 재구성 보드의 일반/동작 줄이기 두 장면, 총 다섯 시퀀스를 약 50ms 간격으로 다시 캡처하고 최종 접촉 시트를 **모두 직접 열어 확인**했다. 12297 검수판에는 반복 가능한 비교를 위해 TNT(88번 셀)와 프로펠러(70번 셀)를 고정 배치했다. 원본 게임의 초기 배치라고 주장하지 않는다.

최종 시트의 `sim +…s`는 입력을 받아 `turn`이 증가한 포인터 이벤트 시점의 엔진 시간에 대한 차이다. `pointerdown`과 처음 승인된 `pointermove`/`pointerup`을 별도로 기록했으므로 첫 스크린샷을 임의로 입력 0초로 지정하지 않았다. Canvas의 투명한 보드 바깥/구멍은 분석용 JPEG에서 검정으로 보인다. 실제 게임 배경의 검정색 결함이 아니다.

다섯 장면 모두 페이지 실행 오류가 없었다. 일반/동작 줄이기 두 판의 최종 **블록 배열·목표·이동 수·턴·상태·잠금**을 비교해 모두 같음을 확인했다. [검수 수치](motion-v6/implementation-motion-report.json)에 입력 시각, 표본 시각, 최종 목표, 비교 결과가 있다. 원시 수백 프레임과 전체 상태 기록은 `/tmp/chroma-motion-v6/`에 두고 저장소에는 접촉 시트와 작은 보고서만 남겼다.

최종 코드에서 단위 297개, UI 34개(새 동작 회귀 10개 포함), Chrome/WebKit 출시 검사 4개, 타입 검사와 배포 빌드가 통과했다. UI에는 누른 채 스와이프, 0.7/1.4배속, 다른 열의 동시 입력, 실제 두 손가락 입력, 취소·홈·재시작·편집기 전환 검사가 포함된다.

독립 엔진 감사에서는 운반 TNT와 추가 스왑, 이미 진행 중인 자동 연쇄의 생성 과정이 겹치는 두 경합을 재현해 수정했다. 예정된 공격 범위를 예약하고, 진행 중인 매치와 실제 착지까지 보호하며, 교환 완료 시 현재 블록으로 다시 판정한다. 대기가 늘어나는 동안 같은 프로펠러의 준비 동작은 이어져 다시 바닥에서 이륙하지 않는다.

200개 시드 × 9개 입력 시점 × 4개 연쇄 파워, 총 7,200개 시나리오와 17,805개 특수 생성에서 원래 구성 블록이 자신의 응집 완료 시 정확히 한 번 제거됨을 확인했다. 최종 빈칸·중복 ID·남은 잠금도 없었다. 이 한정된 조합 검사는 모든 사용자 보드에 대한 증명이 아니다. 재현 명령은 `node scripts/audit-royal-motion.mjs`이며 [감사 스크립트](../../scripts/audit-royal-motion.mjs)를 보존했다.

### 발견 후 수정하고 다시 확인한 부분

- 첫 구현의 TNT는 아직 옅은 별과 부드러운 광원처럼 보였다. TNT만 중앙의 채워진 백색/황색 영역을 넓힌 뒤, 작은 생성 섬광과 구분되는 폭발로 보이는 것을 확인했다.
- 첫 프로펠러는 좁은 날개 세 개와 작은 파란 아래 몸체로 보여 평면적이었다. 연속적인 빨강/금색 회전 면, 두꺼운 아래 몸체, 비행 중 유지되는 크기, 타일 위 그림자가 추가된 최종본에서 깊이감이 나아졌다.
- 처음 선물 파편은 청색/금색 조각이 중심이고 버건디 면이 거의 보이지 않았다. 큰 버건디/붉은 판과 금색 가장자리로 수정된 뒤 최종 연쇄에서 재확인했다.
- 처음 캡처의 긴 벽시계 간격을 애니메이션 지속 시간으로 오해하지 않도록, 최종 증거는 승인된 포인터 이벤트 기준의 **엔진 시간**으로 표시했다.

### 캡처 성능 수치의 해석

매 `requestAnimationFrame`의 시간은 기록하되 JPEG 인코딩은 약 50ms마다 수행했다. 최종 다섯 장면의 RAF 중앙값은 모두 약 16.7ms였다. 생성 장면과 12297 일반 장면에서 각각 250.1ms와 183.4ms의 긴 RAF 간격이 한 번 있었고, TNT 연쇄·라이트볼 조합·동작 줄이기의 최대 RAF 간격은 약 16.8ms였다. 이미지 표본의 최대 간격은 순서대로 266.7, 50.1, 50.1, 200.0, 50.1ms였다.

이 수치에는 `toDataURL` 인코딩, 자동화 입력, 자산 디코딩과 같은 검수 부하가 포함된다. 장면별 한 번의 데스크톱 Chrome 실행이며 **실제 iPhone의 FPS·발열·배터리 성능을 인증하지 않는다.** 긴 간격을 숨기거나 게임 자체가 항상 60fps라고 결론 내리지 않는다.

### 최종 판정과 남는 차이

관찰한 다섯 공통 시퀀스에서 스왑보다 앞선 순간 삭제, 생성 물체의 중복 표시, 목적지 없이 사라지는 비행, 종료되지 않는 표시 잠금을 발견하지 못했다. 최종 엔진 수정 전후의 다섯 장면에서 최종 턴·이동 수·목표·상태·잠금은 동일했고, 직접 확인한 주요 시각 단계도 유지되었다. 기존 v5의 즉시 상태 교체·같은 별 파편·비어 있는 원 폭발보다 동작의 원인과 결과가 분명해졌다.

프로펠러와 파편은 여전히 절차적으로 그린 형태이며 원본의 모든 입체 프레임·모션 블러·곡면 파손 조각과 같지 않다. 로켓/라이트볼의 원본 시간 정보도 이 영상에는 없다. **완전 동일 또는 99% 일치라고 판정하지 않는다.** 이 다섯 장면은 일반 진행의 시각 증거다. 다른 낙하를 기다리는 프로펠러의 연속 준비 단계 등 특수 경합 경로는 별도 엔진/자동화 검사와 구분한다.
