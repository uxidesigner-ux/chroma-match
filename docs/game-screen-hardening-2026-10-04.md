# 게임 화면 안정화 재점검 — 2026-10-04

범위: 게임 화면의 레이아웃, 터치/키보드 입력, 효과 표시, 화면 전환과
일시정지 수명 주기. 캐릭터 모델·의상·게임 규칙·계정·배포 설정은 변경하지 않았다.
기존 `docs/gameplay-stability.md`의 검증 결과를 현재 문제의 해결 증거로
대체하지 않고, 현재 라이브와 로컬에서 다시 재현했다.

## 관찰과 원인

사용자 과제는 보석을 조작하면서 목표·이동 횟수·결과를 안정적으로 읽는 것이다.
행동 가설이나 사용자 조사 결과를 만들어내지 않았다. 아래는 코드와 실제
격리된 게스트 브라우저에서 확인한 사항이다.

| 문제 | 재현 / 원인 | 수정 |
| --- | --- | --- |
| 누르는 순간 보드가 이동하고 선택이 취소됨 | 320×568 / 568×320에서 보드를 80px 스크롤한 뒤 위쪽 일부만 보이는 칸을 누르면, 캔버스 focus가 셀을 자동으로 드러내며 보드가 24px 이동. 입력의 좌표 변경 감지가 정상 터치를 취소함. 라이브 배포본에서도 동일하게 재현. | 포인터 기본 focus를 막고 `preventScroll`로 포커스를 전달. 셀을 드러내는 스크롤은 키보드 탐색에만 적용. 셀 안내와 키보드 포커스는 유지. |
| 점수 메시지 위쪽이 잘림 | 점수는 전체 캔버스 안으로만 제한돼, 스크롤된 보드의 현재 표시 영역 위로 실제 글자/테두리가 약 19px 나감. | 캔버스·보드 스크롤러·게임 화면·창의 교집합으로 표시 범위를 계산. 실제 글자 좌우/상하 범위와 테두리, 상승 이동까지 반영. |
| 높은 연속 효과의 장식이 다른 영역을 침범 | 44px 효과 슬롯 밖으로 확대 테두리가 약 4px 나감. | 고정 48px 슬롯과 슬롯 내부에서만 확장하는 장식. 연속 이벤트/아이템 안내는 보드 크기를 바꾸지 않음. |
| 결과 메시지가 안내로 즉시 교체됨 | `report(6)` 다음 `fusionHint(true)`가 “Legendary!”를 즉시 덮음. | 활성 결과 메시지가 끝난 뒤에만 낮은 우선순위의 조합 안내를 표시. |
| 새 게임이 이전 보드 위치를 이어받음 | 마지막 행까지 이동하고 종료 → 다시 플레이하면 스크롤 182px와 이전 키보드 행이 남음. | 새 게임/이어하기 진입 시 화면 위치·입력 포커스 좌표를 초기화. 다시 플레이의 HUD 반응도 초기화. 저장된 퍼즐과 기록은 변경하지 않음. |
| 극단적으로 짧은 분할 화면에서 보드가 붕괴 | 320×260에서 보이는 게임판 높이가 약 14px까지 줄어듦. | 높이 300px 미만의 좁은 화면에서만 최소 84px 플레이 영역을 확보하고 게임 내부 UI 스크롤 허용. 페이지는 움직이지 않음. |

기본 화면의 수평 넘침과 아이템 안내에 따른 보드 크기 변화는 현재 라이브의
10개 기본 샘플에서는 재현되지 않았다. 이전 수정이 유지되는 부분과 새로
발견한 문제를 구분했다.

## 설계 / 완료 기준

- 기존 목표 / 프로필 / 이동 횟수 3열, 테마 3종, 언어 4종과 원형 버튼을 유지.
- 일반 화면은 HUD와 도구 위치를 고정하고 보드만 스크롤. 아주 짧은 화면은
  모든 UI를 억지로 한 번에 축소하지 않고 내부 스크롤로 접근 가능하게 유지.
- 터치 접촉·아이템 사용·연속 효과 때문에 보드 프레임이나 히트 테스트가
  이동하지 않으며, 포인터 blur/화면 변화는 미완료 접촉을 취소.
- 효과는 정상 모션의 최대 펼침에서도 자기 영역 안에 머무름. 점수 글자는
  고해상도 캔버스에서도 현재 보이는 게임판 내부에 머무름.
- 브라우저 visible viewport의 높이뿐 아니라 좌우/상하 offset도 반영.
  연속 resize/scroll은 프레임당 한 번 반영하고 같은 CSS 값은 다시 쓰지 않음.
- 폴드 힌지와 visible viewport의 교집합을 사용. 핀치 확대는 레이아웃 축소로
  해석하지 않음. 백그라운드에서 게임 진행은 멈추고 돌아오면 이어짐.
- 키보드 탐색, 셀 상태 안내, 포커스 표시, 동작 감소 설정을 보존.
- 보드 6×9, 난수 스트림, 점수, 아이템 소비, 저장/리플레이 규칙을 변경하지 않음.

`impeccable`의 harden / polish 기준을 적용했다. 새 디자인 시스템이나 의존성을
추가하지 않고 기존 토큰과 모달/캔버스 구조를 확장했다. 점수 텍스트가 있을
때만 표시 영역 DOM 측정을 수행하며 매 프레임 캔버스를 재생성하지 않는다.

## 검증 기록

최종 소스 기준 확인:

- TypeScript 검사 통과.
- 전체 단위 테스트 **223개 통과**: 게임 규칙·저장·모델 회귀 포함.
- 게임 안정화 / 화면 크기 / 새 회귀 브라우저 테스트 **38개 통과**
  (주요 검증 35개 + 모바일 접촉/저장 회귀 추가 검증 3개).
  12개 화면 크기, 3개 테마, 4개 언어, 각 목표와 큰 숫자, 200% 텍스트 토큰,
  정상/감소 모션, 아이템, 터치, 일시정지, 종료/정산, resize/힌지를 확인.
  정상 효과는 5개 화면 크기에서 각 테마/언어/효과를 7개 애니메이션 시점에 측정.
  실제 터치 이벤트를 보낸 DPR 3 모바일 에뮬레이션에서 일부만 보이는 행을
  한 번 선택해도 화면이 이동하지 않음을 확인. 기존 규칙의 조합 실행 기록은
  실제 저장 → 재로딩 → 이어하기와 이전 저장/새 게임 전환으로도 재확인.
- Pages 경로(`/chroma-match/`) 프로덕션 빌드 통과. 기존 큰 3D/Firebase 번들
  크기 경고는 남아 있으며, 이번 수정으로 번들 분리나 의존성 변경은 하지 않음.
- 배포용 빌드 게임 테스트 **3개 통과**: 개발용 `window.chroma` 없이 실제
  아이템/키보드 교환/연쇄를 조작. DPR 3에서 실제 캔버스 테두리 포함 점수
  범위, 세로/가로 스크롤 접촉, 다시 플레이, 폴드 크기 변경, 모달 포커스 확인.
- `git diff --check` 통과.

수정 전 새 회귀 3개는 실제로 실패했고, 라이브 배포본의 새 접촉 테스트
2개도 24px 이동으로 실패했다. 새 게임 위치 테스트 역시 수정 전 182px로
실패했다. 첫 확장 검증의 480×320 공간 부족(69px)은 compact HUD 여백으로
수정하고 기존 **70px / 44px** 기준을 낮추지 않은 채 다시 통과했다.
단위 테스트의 소수점 연산 오차에는 1e-9만 허용했다.

증거: `/tmp/chroma-game-hardening.EN9LY8/`의 기본 라이브/로컬 캡처,
수정 전 실패 trace, `final-studio`, `final-touch-save`, `final-release` 캡처와 검사 결과.

## 범위와 한계

Chromium, 모바일 터치/고해상도/화면 크기 에뮬레이션, 제어된 visible viewport와
background 상태 검사다. 실제 iOS Safari, Android WebView, 폴드 센서/노치,
스크린리더 실사용은 별도 확인이 필요하다. 300px 미만 높이의 좁은 화면에서
전체 UI가 동시에 보인다는 보장은 하지 않는다. 최소 플레이 영역과 버튼
접근을 내부 스크롤로 유지하는 명시적 예외다.

게임 단독 검사는 선택적 3D 로딩과 Firebase 네트워크를 차단한 격리 게스트에서
진행했다. 캐릭터/계정 기능 전수 재검증이나 독립 리뷰어의 검토는 아니다.
코드와 실제 플레이/캡처 교차 검토로 발견한 수정 사항을 반영했다.
이 작업은 **라이브를 배포하지 않았다**. 배포 시 별도로 CI와 배포 산출물,
실제 라이브 경로를 확인해야 한다.

## 배포 게이트에서 발견한 추가 회귀

첫 배포 CI `37163808224`는 단위 검사 뒤 브라우저 **125개 통과 / 2개 실패**로
중단됐다. 빌드·Pages 업로드·배포는 실행되지 않았고 기존 라이브를 유지했다.

- 로비 버튼 검사는 기존 150ms 배경 전환의 첫 프레임을 읽었다. 실제 기본
  스타일은 정상이며, 즉시 측정하면 새 게임/이어하기가 모두 빨강이고 전환이
  끝나면 새 게임은 크림색으로 분리된다. 브라우저에서 selector와 실행 중인
  transition, 전환 후 실제 색을 확인했다. 임의 sleep이나 모션 제거 대신
  자동 대기로 정확한 기본 색을 검증하고, 호버 색과 기존 크기/배치 기준도
  함께 검사하도록 강화했다.
- Linux의 classic scrollbar 환경에서는 320px → 1280px 전환 중 media query만
  바뀐 임시 프레임을 `resize` 핸들러가 측정했다. 두 화면의 최종 캔버스 크기가
  같으면 ResizeObserver가 다시 호출되지 않아, 표시/입력 셀 크기는 44px인데
  renderer는 **42.333px**를 유지했다. 로컬에서도 총 17px gutter를 확보하면
  같은 전환이 **41.833px**로 실패했다. 창 resize/orientation 측정은 shell의
  프레임 업데이트 이후로 합쳐 수행한다. 실제 크기 변경의 ResizeObserver는
  유지해 스크롤/정상 리사이즈를 지연시키지 않는다.
- 반응형 회귀에 classic gutter를 포함하고 44px 기준 외에도 실제 CSS 크기와
  renderer 셀 크기가 1e-9 이내로 같음을 검사했다. 기존 게임 기록·목표·이동
  횟수·키보드·버튼 기준은 그대로 유지했다. 두 실패 경로는 수정 후 통과했다.

실패 trace, 로비 전환 관찰, classic gutter 수정 전 실패와 수정 후 검증 자료는
`/tmp/chroma-game-release.EYIbIh/`에 보존했다. CI·배포 설정과 타임아웃,
최소 터치 크기, 기존 기능 검증은 낮추지 않았다. 배포 성공 여부는 이후
전체 CI 결과와 실제 라이브 산출물·플레이 검증으로 별도 확정해야 한다.

추가 수정의 로컬 최종 검증: 타입 검사, 단위 **223개**, 게임 화면/반응형
브라우저 **36개**, 로비 기본/호버 위계 **1개**, Pages 경로 프로덕션 게임
**3개**, 프로덕션 빌드와 diff 검사 통과. 변경은 resize 측정 순서와 회귀
검사/기록으로 한정되며 새 의존성·테마/모델·게임 규칙 변경은 없다.
