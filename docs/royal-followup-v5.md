# Main 반영 후 플레이·시작 성능 개선

2026-11-23. v4 리뉴얼은 `7a9ba547a3d2068dac971bd13b9cc62133c076f5`로 main에 반영했다. [GitHub 검사와 Pages 배포](https://github.com/uxidesigner-ux/chroma-match/actions/runs/45104725861)가 성공했다. 이후 아래 문제를 실제 재현해 다음 개선 대상으로 정했다.

## 재현한 문제와 변경

| 문제 | 변경 |
| --- | --- |
| 매 실행마다 8개 아틀라스의 픽셀 연결 영역을 검사하고 WebP로 다시 인코딩해 첫 화면을 지연시킴 | 동일한 39개 스프라이트를 미리 가공한 로컬 팩으로 제공. 원본 이미지와 추출 스크립트는 보존. |
| 성 이미지 응답이 끝나지 않으면 진입 버튼을 눌러도 홈에 들어가지 못함 | 배경 준비 시간에 상한을 두고 대체 화면으로 진입 가능하게 처리. |
| 사용자 보드에서 홈에 돌아오면 캠페인 레벨 1로 표시됨 | `나만의 보드`와 보드 이름을 접근성 문구에 표시하고 실제 사용자 보드를 이어서 실행. |
| 로켓·TNT·라이트볼 조합은 칸을 제거하지만 해당 빔·폭발 이벤트를 전달하지 않음 | 실제 공격 좌표와 범위를 효과에 전달. 기존 공격·이동 규칙은 유지. |
| 라이트볼 광선의 목적지와 승리 축하 효과의 좌표가 비어 있음 | 제거 대상과 보드 좌표로 광선·축하 효과를 표시. 효과 개수를 제한하고 동작 감소 설정 적용. |
| 키보드에서 Enter가 특수 블록을 즉시 발동해 조합 불가 | `Shift+방향키`로 바로 옆 블록과 교환. 일반 방향키 이동과 Enter 단독 발동 유지. |

## CI 연결

푸시용 인증에 workflow 수정 권한이 없어 기존 `.github/workflows/ci.yml`을 유지했다. CI가 호출하는 `test:game-ui`와 `test:release`를 현재 Royal 게임 검증으로 연결하고, CI의 release 사전 단계에서 WebKit을 설치한다. 이전 공개판 검증 명령은 `test:legacy-game-ui`, `test:legacy-release`로 보존한다. 검사를 생략하거나 배포의 성공 조건을 완화하지 않았다.

## 확인 범위

첫 실행 측정은 같은 Mac의 Chrome, 로컬 개발 서버, 390×844 화면에서 새 브라우저 컨텍스트로 수집했다. 측정 지표는 진입 화면이 표시되기까지의 시간이다.

| 조건 | 변경 전 | 변경 후 3회 |
| --- | --- | --- |
| 기본 CPU | 1,669ms | 172 / 92 / 88ms |
| CPU 4배 제한 | 6,144ms | 330 / 329 / 324ms |

CPU 4배 제한에서 가장 긴 메인 스레드 작업은 1,891ms에서 135ms로 줄었다. 변경 후 기본 CPU 측정에서는 50ms 이상 작업이 관찰되지 않았다. 새 실행은 약 1.18MB의 JSON 팩 한 번만 요청하며 원본 아틀라스 8개는 요청하지 않았다. 압축된 팩은 약 880KB다. 39개 WebP 데이터는 이전 런타임의 결과와 바이트 단위로 같았고, 재생성 `--check`도 통과했다.

위 수치는 로컬 비교이며 실제 iPhone, 외부 모바일 네트워크, 모든 기기의 시작 시간을 보장하지 않는다. 기능 테스트와 효과 확인도 원작과의 정량적 일치율을 인증하는 검사가 아니다.

로켓+TNT 조합의 같은 보드·시드·이동을 직접 확인한 화면: [일반 효과](royal-preview/v5-combo-normal.png) · [효과 줄이기](royal-preview/v5-combo-calm.png). 두 경우 모두 이동은 20→19, 목표는 같은 992로 기록되었다. 반복 이벤트 검사에서 효과 50개·파티클 450개·잔상 100개 상한을 확인했다.

스프라이트 원본을 수정할 때는 `npm run sprites:build`를 실행한다. `npm run build`는 브라우저를 실행하지 않고 원본 SHA256과 39개 WebP 항목을 확인해 오래된 팩의 배포를 막는다. 전체 픽셀 재현성 검사는 `node scripts/build-royal-sprites.mjs --check`로 수행한다.
