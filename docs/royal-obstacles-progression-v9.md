# 장애물 파손 단계와 연속 레벨 v9

장애물의 남은 타격 수를 폭발 순간뿐 아니라 정지한 보드에서도 읽을 수 있게 했다. 게임 엔진의 피해·수집 규칙은 유지하고 현재 HP와 재고를 그림·타격 표식·선택 안내에 함께 연결한다.

## 장애물 표현

| 종류 | 계속 남는 파손 표현 | 완전히 제거하기까지의 유효 타격 |
|---|---|---|
| 나무상자 | 대각 보강판 제거, 드러난 판자, 갈라짐과 부서진 모서리 | 현재 HP |
| 선물상자 | 포장·리본·봉인·열린 상자 단계, 포장 찢김 | 현재 HP. 장난감 재고를 곱하지 않음 |
| 얼음 | 균열, 투명도와 모서리 변화, 엔진의 끝 칸 해제 | 현재 HP. 편집 보드의 길이와 별개 |
| 돌 | 커지는 균열과 깨진 모서리 | 현재 HP. 파워업·도구 타격만 유효 |
| 뻐꾸기 | 나무 테두리 균열, 현재 껍질의 보강재, 남은 새 | 현재 HP + (남은 새 − 1) × 초기 HP |
| 다이너마이트 | 금속 테두리 손상, 현재 껍질의 보강재, 남은 폭발 재고 | 현재 HP + (남은 재고 − 1) × 초기 HP |

모든 종류에 같은 금색 타격 표식을 쓴다. 1~4회는 작은 마름모 개수, 그 이상은 숫자로 나타낸다. 내용물 수는 별도 아이콘과 `×개수`로 구분한다. 반복 장애물이 새 껍질로 돌아가도 총 남은 타격 표식은 증가하지 않는다. 편집기에서 추가한 높은 HP도 보강재가 하나씩 사라지고 파손도가 변한다. 불규칙한 다칸 장애물은 실제 점유 칸에 맞춰 그림과 피격 섬광을 자른다.

장애물을 누르면 남은 타격 수를 알려주며 키보드·스크린 리더 안내도 HP가 바뀌면 갱신된다. 뻐꾸기 문이 닫힌 상태나 다이너마이트의 색 조건처럼 무효 타격이 가능한 규칙도 안내한다. 효과 줄이기를 켜도 정적인 파손 표현은 유지한다.

## 레벨 수와 저장

- 1~32판은 직접 구성한 초반 캠페인이다.
- 33판 이후는 요청한 번호로 즉석 생성한다. 12297은 공유 영상에 근거한 별도 참고 판이다.
- 이전 999999판 제한을 제거해 999999 → 1000000 이후도 다음 판으로 진행한다. 지원 번호는 JavaScript/JSON에서 정확히 저장할 수 있는 양의 안전한 정수, 최대 9,007,199,254,740,991이다.
- 기존 판 구성은 유지한다. 큰 번호의 상위 비트를 시드에 반영해 2³² 간격의 강제 반복을 없앴다. 유한한 형상·기믹 조합이므로 모든 판의 완전한 고유성이나 원작과 같은 난이도는 보장하지 않는다.
- 완료 번호는 연속 범위로 압축하고 최근 256개 번호를 함께 저장한다. 기존 저장 데이터를 읽을 때 변환하며, 오래된 완료 판도 최초 보상을 다시 지급하지 않는다.

레벨 생성·검증 기준과 난이도 설명은 [레벨 데이터 문서](../src/royal/LEVELS.md)에 정리되어 있다.

## 검수

- 단위 테스트 354개 통과: 여섯 장애물의 타격 계산, 재고 교체 시 남은 횟수 감소, 고레벨 생성·진행·저장, 기존 완료 목록 압축과 중복 보상 방지 포함.
- 전체 게임 UI 63개 통과. 마지막 테두리·긴 번호 줄바꿈 수정 후 관련 10개를 재검증해 모두 통과했다. 실제 망치 입력으로 여섯 재질의 정지 화면 변화, 닫힌 뻐꾸기의 무효 타격 전후 이미지 동일성, 선물·얼음의 HP/재고 구분, 반복 껍질의 총 타격 감소를 확인했다.
- 캠페인 999999판을 실제 도구 입력으로 완료하고 결과 창의 다음 판 버튼으로 1000000판에 진입했다. 고레벨 설정 저장·홈 복원, 마지막 번호 페이지, 375×667 홈 버튼의 실제 글자 영역도 확인했다.
- 최종 배포 빌드의 Chrome/WebKit 검사 4개 통과: 프로젝트 경로, 자산, 저장, 오프라인 실행, 캐시 격리.
- iPhone 앱용 오프라인 묶음도 갱신했다. Swift 문법·프로젝트·번들 정적 검사 통과. 이 환경에 Xcode/iOS SDK가 없어 네이티브 컴파일·설치·실기기 진동은 검증하지 않았다.
