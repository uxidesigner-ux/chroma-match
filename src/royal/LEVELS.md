# 개인용 레벨 데이터와 편집 규칙

이 캠페인은 공개 도움말에서 확인한 기믹을 사용해 만든 **개인용 레벨 구성**이다. 원작 전체 레벨 파일이나 난이도 공식을 확보한 것은 아니다.

## 구성

- **1–32:** 직접 정한 크기·형상·목표·이동 수·기믹 조합. 일반 캠페인은 최대 **8열×9행**으로 제한해 모바일 블록 크기를 확보한다. 처음에는 색 수집, 이후 상자→선물→젤리→얼음→뻐꾸기→돌→다이너마이트를 경험한다. 이 등장 순서는 이 프로젝트의 튜토리얼이며 원작의 해금표가 아니다.
- **33번 이후:** 요청한 레벨 번호로 그때 생성한다. 미리 모든 판을 파일로 만들거나 내려받지 않는다. 7–8열, 8–9행, 12가지 형상 계열의 **952개 고유 마스크**, 여섯 기믹 조합과 여섯 장애물 배치 패턴을 사용한다. 목표는 실제 배치된 개체 수에서 도출하며 모바일 HUD에 최대 네 종류를 표시한다. 12,000·20,000·1,000,000번 이후도 같은 방식으로 이어진다.
- **12297:** 사용자가 확인한 영상의 9×11 보드 마스크와 2×2 다이너마이트·뻐꾸기 위치를 참조한 별도 재구성. 외곽과 기믹을 참고했지만 원작 시작 상태의 완전 복제는 아니다.

레벨마다 새 정의를 반환하므로 편집기에서 원본 배열을 변경해도 다른 세션의 캠페인은 변하지 않는다. 레벨 설계의 시드는 고정되며, 재도전 때 일반 블록을 새로 배치하는 정책은 게임 시작 옵션에서 별도로 정한다.

기존 999999번 종료 제한을 제거했다. 지원 범위는 JSON과 JavaScript에서 정확하게 보존되는 양의 안전한 정수, 최대 **9,007,199,254,740,991**번이다. 이 마지막 번호에서는 증가를 멈추며 1번으로 돌아가지 않는다. 문자 그대로 무한한 번호 체계는 아니다. 큰 레벨 번호의 상위 비트도 시드에 섞어 2³²번 간격의 강제 반복을 없앴다. 형상·기믹 조합의 종류는 유한하므로 비슷하거나 같은 판이 절대 나오지 않는다고 보장하지 않는다.

1–32번은 기존 8×9 조정판의 배치·목표·이동 수를 유지한다. 레벨 23은 8×9 테라스, 얼음 8개·새 2마리·31회 이동이다. 12297 참고 판과 5–12칸 사용자 보드는 크기 제한의 예외이며 가져오기·내보내기 크기를 바꾸지 않는다. 이번 생성기 변경은 33번 이후의 일반 판에 적용한다. 레벨 번호의 시드는 유지하지만 형상·장애물·난이도·이동 수는 아래의 새 규칙으로 재구성한다. 완료 번호·별·설정은 바꾸지 않으며 같은 번호를 다시 완료해도 최초 보상을 다시 지급하지 않는다.

완료 기록은 연속 번호 범위로 압축한다. 예를 들어 1번부터 20,000번까지 완료하면 범위 하나로 저장하고, 최근 번호 목록은 256개만 유지한다. 옛 완료 번호를 범위에서 확인하므로 목록에서 빠진 판을 다시 깨도 최초 보상을 중복 지급하지 않는다. 기존 저장 목록은 읽을 때 자동으로 변환하며 설정·별·코인·완료 기록을 유지한다.

## 난이도

Normal, Hard, Super Hard, Extremely Hard의 태그는 원작의 공개 분류를 사용한다. **개별 태그 배치와 수치 조정은 개인용 설계**다. 원작이 특정 주기나 선형 공식으로 난도를 올린다고 가정하지 않는다.

초반 캠페인은 기믹 단독 학습과 복합 과제를 번갈아 배치한다. 생성판의 10판 리듬은 **회복→보통→보통→어려움→보통→회복→보통→어려움→보통→도전**이다. 마지막 도전은 보통 매우 어려움, 네 번째 묶음마다 극도로 어려움이다. 회복판은 낮은 점유율·적은 기믹 조합·추가 이동으로 쉬어가는 구간을 만든다. 실패 횟수·결제·플레이 이력에 따른 숨은 조정은 없다.

성장값은 `min(1, log1p((레벨−33)/40) / log1p(100000/40))`로 완만히 증가하며, 약 10만 판 뒤에는 상한을 유지한다. 상자 HP 2–4, 선물 HP 3–5, 돌 HP 2–4, 얼음 길이·HP 2–3, 둥지 재고 2–4를 사용한다. 다이너마이트는 1회 타격·재고 2로 유지한다. 선물 재고는 한꺼번에 나오는 수집량이므로 타격 난도 증가로 계산하지 않는다.

이동 수는 실제 배치 결과의 작업량으로 계산한다. 기본 타격량은 일반 장애물의 HP, 둥지·다이너마이트의 `HP×재고` 합이다. 돌·둥지의 제약과 미도포 젤리에는 가중치를 주고, 보드 전체를 치는 다이너마이트의 보조 효과는 일부 빼서 24–54회 범위로 정한다. 같은 크기라도 실제 장애물 작업량에 따라 이동이 달라진다. 목표는 항상 실제 배치된 수량에서 다시 계산한다.

개발 중 연속 100판씩 측정한 구조 지표는 다음과 같다. **타격량은 성공률이나 필요한 실제 이동 수가 아니다.** 한 매치·파워업으로 여러 목표를 동시에 처리할 수 있다.

| 시작 레벨 | 평균 타격 작업량 | 평균 장애물 점유율 | 평균 이동 수 |
|---|---:|---:|---:|
| 33 | 21.1 | 29.7% | 30.4 |
| 1,003 | 27.2 | 33.1% | 32.0 |
| 12,003 | 35.2 | 37.1% | 35.6 |
| 1,000,003 | 48.7 | 40.0% | 39.9 |

## 생성판 형상과 배치 보장

`campaign-geometry.ts`는 크기·반전·얕은 가장자리 홈을 조합하고, 실제 마스크가 같은 항목을 제거한다. 연결되지 않은 형상·너무 좁은 끝 칸·3×3 공간이 없는 형상은 제외한다. 계열별 후보를 섞어 순환하므로 카탈로그 끝과 처음을 포함해 **연속 두 일반 판의 실제 마스크가 같지 않다**. 카탈로그는 첫 생성 요청에서 한 번 만들고 재사용한다. 번호에 비례한 반복 생성이나 이전 판 재귀 호출은 없다. 전체 모양의 종류는 유한하며 반복 주기 이후 같은 마스크를 쓸 수 있다.

`campaign-generator.ts`의 장애물 배치는 군집·가로 띠·중앙·가장자리·대각선·분산 패턴을 번갈아 사용한다. 항상 다음 조건을 지킨다.

- 장애물 점유율 최대 52%, 일반 블록 칸 최소 20개.
- 장애물 없는 3×3 공간과 일반 블록 영역 전체의 연결성.
- 일반 블록 칸 중 최소 70%가 가로·세로 3개 또는 2×2 매치에 참여 가능한 위치.
- 돌을 제외한 모든 장애물 옆에 실제 매치 가능한 일반 블록 칸이 하나 이상 존재.
- 젤리 시작점은 장애물이 없는 매치 가능한 위치에 배치.
- 각 기믹을 우선 하나씩 배치한 뒤 패턴을 채우고, 빈 3×3 후보는 최대 여섯 곳까지만 시도.

이 조건은 연쇄·이동을 시뮬레이션하기 전의 구조적 접근성을 보장한다. 플레이 중 실제 색 배치와 사용한 파워업에 따라 해법은 달라진다.

이는 구조적으로 불가능한 목표를 막는 기준이다. 모든 판을 제한 이동 안에 무부스터로 해결할 수 있다는 수학적 증명이나 원작과 동일한 성공률을 의미하지 않는다. 개인 설정에서 이동 수·도구를 조정할 수 있다.

## 레벨 12297 재구성의 근거와 차이

| 항목 | 적용 |
|---|---|
| 레벨 번호 | 사용자 설명 및 추가 사진의 12297 |
| 보드 | 9열×11행. 위 4행 전체, 아래 7행의 4·5열은 빈 공간 |
| 다이너마이트 | 4·5열 / 3·4행을 점유하는 2×2 개체, 재고 8 |
| 뻐꾸기 | 7·8열 / 3·4행을 점유하는 2×2 개체, 새 2 |
| 장난감 | 긴 선물상자 9개에 장난감 2개씩 배정, 총 18 |
| 젤리 | 보드 85칸 중 4칸을 칠한 상태로 시작, 남은 81칸 |
| 이동 | 개인 플레이용 32회. 영상의 22회나 사진의 9회는 남은 이동이므로 시작 이동으로 사용하지 않음 |
| 일반 블록 | 시드에 따른 새 배치. 영상의 정확한 원본 시작 배치가 아님 |

선물상자 위치·장난감 배분·시작 젤리 4칸·시작 이동은 플레이 가능한 재구성을 위해 정한 값이다. 영상의 중간 잔량을 원작의 최초 목표량이라고 주장하지 않는다. UI와 내보내기 데이터에 `reference-reconstruction` 출처를 유지한다.

## JSON 가져오기

`validateLevel`은 읽은 JSON 객체를 검증하고 새 배열·객체로 복사한다. 실패하면 `level` 없이 한국어 `errors`를 반환한다. 알 수 없는 속성은 제거해 숨기지 않고 오류로 표시한다.

- 형식 `version: 1`, 레벨 번호 1–9,007,199,254,740,991의 안전한 정수, 보드 각 변 5–12칸(최대 144칸).
- 이름 1–80자, 설명 최대 1000자, 이동 1–200, 색상 3 또는 4, 시드 0–4294967295.
- 보드 마스크는 정확한 행·열 수의 0/1 문자열 배열.
- 최소 12개 유효 칸, 장애물을 제외하고 최소 9개 빈 칸, 일반 매치가 가능한 연속 칸이 필요.
- 장애물 ID 중복·점유 중복·보드 밖/빈 공간 배치 금지. 한 개체는 연결된 1–16칸. 내구도 1–12, 재고 1–100.
- 목표는 중복 없는 1–8개. 색 목표는 사용 가능한 색이어야 하며 아이템 목표량은 실제 재고보다 많을 수 없다.
- 젤리 목표는 시작 젤리가 있어야 하고, 미도포 칸 수를 초과할 수 없다. 분리된 보드마다 젤리 씨앗이 필요하다.
- 초기 블록은 보드 밖·장애물·다른 블록과 겹칠 수 없다. 특수 블록 종류는 정의된 다섯 방향/종류 값만 허용한다.

캠페인의 얼음은 세로 3칸·3회 타격으로 두며 타격할 때 끝 칸이 풀리는 길이형 기믹이다. 수집 목표에서 `box`, `ice`, `stone`은 개체 수이며 HP 합이 아니다. `gift.stock`은 파괴 시 나오는 장난감 수, `cuckoo.stock`은 남은 새, `dynamite.stock`은 남은 폭발 횟수다. `deriveGoals`는 이 실제 재고와 아직 칠하지 않은 젤리 칸으로 목표를 다시 계산한다. 장애물도 젤리도 없는 편집 보드는 왕관 20개 수집이 기본값이다.
